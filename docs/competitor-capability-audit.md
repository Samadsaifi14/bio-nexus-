# Competitor capability audit and implementation boundary

Reviewed 2026-10-13. This is a public-documentation and source-code audit, not an inspection of commercial binaries or authenticated vendor deployments. REA is a workflow aid; installing it does not establish feature parity or scientific validation. Paths below are relative to `bioai-platform/backend/app/`. Presence of code is implementation evidence, not evidence that production compute is configured or a benchmark passed.

## Corrections to the proposed comparison

* Galaxy has AI-assisted error explanations and workflow-related assistance. “No AI interpretation” is an unsupported absolute claim. Compare specific explanation tasks with a dated deployment and common input instead.
* Geneious Prime is a desktop application, but its official feature page also documents cloud workspaces and server execution through a CLI. “Desktop-only” should not imply that it cannot collaborate or use remote resources.
* Benchling and SnapGene have substantive sequence analysis and design capabilities; grouping them simply as lab notebooks understates their scope.
* OmicsBox spans genome, transcriptome and functional analysis. “Narrow scope” needs a specified workload.
* Latch workflows are configurable scientific workflows; “genomics-only” is not established by the cited documentation.
* Partek Flow supports local/server/cluster/cloud installations; it is not exclusively a cloud service.
* BIOVIA supplies a free Visualizer as well as commercial modeling software. Blanket license-price claims require current quotes for a specific package.
* Seqera now documents integrated AI that can inspect failures and launch workflows. Terra supplies introductory reproducible workspaces. “Not for students” is a positioning hypothesis, not a verified limitation.
* General LLMs and bio-agents are not one product. Tool-connected agents can execute reproducible workflows; evaluate the actual agent, tools, version, prompts and artifact record.

No pricing, clinical validation, usability superiority, queue-time superiority, or scientific winner is established by this audit.

## Scientific corrections: pre-change source baseline

1. `tools/function_predict.py` already implements `interpro2go-evidence-v1`: sequence retrieval, InterProScan and InterPro-to-GO mapping. Its module explicitly rejects composition-derived probabilities and excludes unsupported EC inference. Keep this narrower evidence claim. Check retrieval failures and asynchronous completion; do not replace it with a weaker composition classifier or imply DeepFRI equivalence.
2. `tools/castp.py` already defaults to `method="fpocket"` and separates CASTp, fpocket and the BioNexus heuristic. Audit frontend labels, engine availability, stderr/errors, parser evidence and heuristic-specific fields before calling the whole path fixed. Real CASTp geometry cannot be asserted from SASA clustering.
3. `tools/oligo_qc.py` currently documents heuristic Tm/hairpin/dimer estimates. Replace those estimates with `primer3-py` nearest-neighbour functions, recording salts, magnesium, dNTPs, oligo concentration, temperature, engine version and units. Never silently fall back to heuristic values under the thermodynamic label; invalid/unsupported primers must return explicit diagnostics. Primer thermodynamics do not establish genome-wide specificity or experimental PCR success.

## Prioritized acceptance criteria

| Priority | Deliverable | Evidence required before release claim |
|---|---|---|
| P0 | Primer thermodynamics and correct functional/pocket identities | Fixed-sequence agreement with direct Primer3 calls; structured missing-engine/error cases; evidence/method labels survive exports and UI. |
| P1 | Independent restriction/plasmid and primer-binding workspace | Linear/circular origin fixtures; both-strand coordinates; digest fragment lengths sum to template; no invented cut for ambiguity; visible/exportable inputs and method. |
| P1 | Workflow replay/provenance interoperability | Pinned manifest, input hashes, task outcomes and artifact hashes; planned/unavailable never presented as executed; ownership tests for private inputs. |
| P1 | Production RNA-seq usability and durable execution | Actual executor availability plus accession/count/reference/sample/contrast provenance and DESeq2 plots; normalized inputs trigger real retrieval/re-quantification rather than rounding. |
| P2 | Annotation/enrichment expansion | Database snapshots, background universe, adjusted P values and domain evidence; independent fixtures and unavailable diagnostics. |
| P2 | Structure/drug-discovery expansion | Executed multi-complex pose validation, preparation/export evidence and MD assumptions. Affinity/FEP claims require a distinct validated method. |

These are acceptance boundaries, not a claim that every listed feature has been implemented in this change. The release summary must name actual changed paths, executed checks and remaining operational dependencies. Feature parity with the named platforms would require a much larger, workload-specific evaluation.
